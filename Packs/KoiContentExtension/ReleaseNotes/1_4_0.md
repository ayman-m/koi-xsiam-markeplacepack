#### Correlation Rules
##### New: KOI Ext - Gateway Approval Request
Added a **REAL_TIME** correlation rule on `koi_koi_raw` that fires when a Supply Chain Gateway
**access request** appears (an `approval_requests` submission — the observable proxy for a block,
since the gateway's own block verdict never reaches XSIAM). It maps the item, marketplace, requester
and risk into the KOI alert fields via `DATASET_MAPPING` — no classifier, no mapper. The extraction
mirrors the parsing rule and was validated against a live tenant.

#### Incident Types
##### New: KOI Gateway Approval
Added the **KOI Gateway Approval** incident type, `autorun: true` bound to **KOI Ext - Gateway
Approval Triage** and reusing the KOI Supply Chain Alert layout. This closes the loop from the
correlation rule's alert to the triage playbook, which previously had no trigger.

#### Playbooks
##### KOI Ext - Gateway Approval Triage
Wired the playbook's inputs to default from the alert fields the correlation rule populates
(`${alert.koiitemname}`, `${alert.koimarketplace}`, `${alert.koideviceuser}`,
`${alert.koirisklevel}`), so it runs correctly on autorun — the same `${alert.*}` convention as the
Alert Triage chain.

#### Modeling Rules
##### KoiContentExtension
Mapped the approval fields into XDM (both validated on live rows):
- **`xdm.event.outcome` is now decision-aware.** `action` is null on `approval_requests` rows, so a
  **rejected** request previously mapped to `SUCCESS` (the default) — a real defect. A rejected
  decision now maps to `OUTCOME_FAILED`; a submission stays `SUCCESS` (the submission itself
  succeeded; its verdict is pending).
- **`xdm.target.user.username`** now carries the requester on approval rows (the user the exception
  is *for*), while `xdm.source.user.username` stays the event actor. The identity is self-asserted on
  agent-less endpoints — never key trust on it.
